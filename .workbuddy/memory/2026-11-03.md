## 本地启动方式（已确认）

- 仓库根目录**没有** `package.json`，所有脚本在 `web/package.json`；必须 `cd web` 再执行，否则报 `error: Script not found "dev"`。
- 正确步骤：`cd web` → `bun install` → `bun run dev`（`vite --host 0.0.0.0 --port 3000`），访问 http://localhost:3000。
- 本次已补装依赖（node_modules 从 33 个包补到 577 个）；`bun install` 末尾的 `postinstall ENOTCONN` 是沙箱限制，不影响结果。
- **禁止**为让根目录能跑 `bun run dev` 而在根目录新增 `package.json`，尤其不能带 `"type": "module"`：Vercel 会据此改变 `api/*.js` 的模块解析方式，导致 `api/proxy.js`（CommonJS）加载失败。
- 验证结果：首页 200、`src/main.tsx` 编译无错、`/ai-proxy/` 中间件生效（上游不通返回 502）、`/api/proxy` 身份接口 200。

## 本机 bun 1.3.0 无法 spawn 子进程（重要）

- 现象：`bun run dev` / `bun run build` 只打印 `$ vite ...` 后永久挂起，无 VITE banner、端口不监听；`bun install` 的 postinstall 报 `ENOTCONN`。
- 定位：`bun run` 执行最简 `node -e "console.log(1)"` 同样挂死，与 vite、0.0.0.0 绑定、3000 端口均无关；直接 `node ./node_modules/vite/bin/vite.js ...` 1.9s ready，`npm run dev` 2.3s ready。
- 结论：本机 Bun 1.3.0（Windows）spawn 子进程坏了，不是项目问题。改用 npm / node 执行脚本即可。
- 已改 `web/package.json`：`dev` = `node ./node_modules/vite/bin/vite.js --host 0.0.0.0 --port 3000`，`start` 同理加 `preview`；`build` 保持 `vite build`（Docker 用 oven/bun 纯镜像无 node，不能改）。
- 本地启动方式：`cd web` → `npm run dev`（或 `npx vite`），不要用 `bun run dev`。
- 待观察：若 Vercel / Docker 的 `bun run build` 也超时，把 `vercel.json` 的 buildCommand 改为 `cd web && npm run build`。

## /ai-proxy 报 fetch failed 的原因（本机网络）

- 现象：`/ai-proxy/?target=https://moonup.dev/...` 返回 `{"error":"代理请求失败","detail":"TypeError: fetch failed"}`。
- 本机网络：系统代理 `127.0.0.1:7897`（Clash 类客户端，端口 LISTENING），ProxyEnable=1；但 Node 的 `fetch` **不读 Windows 系统代理**，Vite 中间件是直连，访问 Cloudflare（moonup.dev）超时。
- 解法：启动前设 `NODE_USE_ENV_PROXY=1` + `HTTPS_PROXY`/`HTTP_PROXY=http://127.0.0.1:7897`（Node 22.22.2 支持该变量，会告警 EnvHttpProxyAgent experimental）。实测走 7897 后正常返回 401（仅缺 API Key）。
- 注意：Node 直连在该沙箱里反而能通（WorkBuddy 沙箱有透明出口），所以不能只用沙箱结果判断用户网络。
- 已改进 `vite.config.ts` 的 catch：打印 `target` + `cause.code` 到终端，502 响应带 `detail`/`target`/`hint`；中英文 quick-start 文档补充「网络需要代理时」小节。
