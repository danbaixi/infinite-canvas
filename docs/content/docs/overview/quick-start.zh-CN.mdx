# 快速开始

如果你只是想先把项目跑起来，优先部署或启动 `web/` 前端。

## Vercel 部署

在 Vercel 中导入仓库即可：根目录 `vercel.json` 会构建 `web/`，并把 `api/proxy.js` 一并部署为 Serverless 函数。

默认就走同源的 `/api/proxy`：请求由这个 Serverless 函数转发到你的模型服务，浏览器不直接访问第三方域名，跨域和网络可达性问题一次解决，不需要本机再运行任何命令。默认不限制目标域名，任何 OpenAI 兼容地址都能转发。

如果担心被人当成公开代理，可以在 Vercel 环境变量里收紧范围：`PROXY_ALLOWED_HOSTS=api.openai.com,your-relay.com`（逗号分隔，支持 `*.example.com`）；也可以加 `PROXY_TOKEN=xxx`，并在配置 → 请求代理的地址后带上 `?token=xxx`。

想恢复浏览器直连，打开配置 → 请求代理，把开关关掉即可。

Vercel 函数对单次请求和响应的体积上限是 4.5 MB，图生图上传大图或返回大尺寸 base64 时可能触发 413，这种场景更适合把 `canvas-proxy` 单独部署到支持长连接和更大请求体的服务上。

## 本地启动

```bash
git clone git@github.com:basketikun/infinite-canvas.git
cd infinite-canvas
cd web
bun install
bun run dev
```

启动后访问：

```text
http://localhost:3000
```

跨域请求默认就会被改写成同源的 `/api/proxy?url=<目标地址>`，由本地 Vite 中间件（线上则是对应的 Serverless 函数）转发并流式回传，不需要额外启动代理进程，浏览器也不会直接访问第三方域名。想在本地改用独立的代理进程，把配置里的模式切到「本地代理」即可；想彻底关掉代理恢复直连，关掉开关即可。

（`/ai-proxy/?target=` 是另一条等价的本地路径，仅在设置 `VITE_API_PROXY` 相关场景下才会用到。）

### 网络需要代理时

转发由 Node 的 `fetch` 完成，而 Node 默认**不读取系统代理**（Windows「Internet 选项」里那个代理），所以浏览器能打开的地址在这里仍可能超时，表现为：

```json
{"error":"代理请求失败","detail":"UND_ERR_CONNECT_TIMEOUT","target":"https://..."}
```

这时在启动前把环境变量和代理地址一起设好，让 Node 走自己的代理客户端：

```powershell
$env:NODE_USE_ENV_PROXY="1"
$env:HTTPS_PROXY="http://127.0.0.1:7897"
$env:HTTP_PROXY="http://127.0.0.1:7897"
npm run dev
```

`7897` 换成你自己的代理端口。之后如果关闭了代理客户端，记得清掉这两个变量（`Remove-Item Env:HTTPS_PROXY`），否则转发会继续尝试连一个不存在的代理而失败。

## Docker 启动

如果你需要基于当前源码构建镜像：

```bash
docker build -t infinite-canvas .
docker run --rm -p 3000:3000 infinite-canvas
```

## 首次使用建议

- 先打开右上角配置弹窗，填入自己的 `Base URL`、`API Key` 和模型名。
- 如果需要提示词仓库内容，打开 `/prompts` 会由浏览器前端直连拉取并缓存到 IndexedDB。
- 如果需要跨设备同步画布、素材和生成记录，可在配置弹窗中填写 WebDAV。

## 说明

- 当前画布项目和“我的素材”主要保存在浏览器本地，WebDAV 同步需要用户自行配置。
- AI API Key 保存在浏览器本地，并由前端直接请求 OpenAI 兼容接口。
